# 生产流程

## 任务模式

- `inspect`：查看状态、检查文件、审稿或汇报。只读，默认零外部模型调用。
- `plan`：创建或修改总纲、分卷、章节契约。除非用户明确要求 AI 生成，否则先在 Codex 内完成。
- `chapter`：写一章或修一章。一个草稿调用，按 blocker 条件决定是否有一次修订。
- `batch`：自动生成多章或整书。只有用户明确要求完成后统一查看时启用；不逐章询问，但必须逐章落盘和留断点。
- `export`：组装最新确认版本并做整书门禁；不生成新剧情。

## 初始化

初始化作品前收集或从用户上下文推断：书名、题材、读者、篇幅、POV、风格、必须元素、禁止元素、剧情自主权、五库共文/专有词库模式。只有会实质改变创作方向而无法安全推断的缺口才询问。

随后：

1. 创建标准目录和项目配置。
2. 写清开篇钩子、主角迫切目标、持续压力、关系线和可验证的终局状态。
3. 建立角色表、绝对时间线起点、证据/关键物件表、禁用名词。
4. 先完成全书因果骨架和结局闭环，再拆章节。不能只规划“下一章继续查”。
5. 给每章一个主任务；相邻章节用“因此 / 但是”连接，不能只是“然后”。

## 章节契约

写正文前，用紧凑结构记录：

```markdown
- 主任务：本章必须改变什么
- 次任务：关系、伏笔或五库语义中的次要任务
- 入口状态：人物位置、时间、进行中的行动、已知/未知、关键物件
- POV 边界：视角人物能观察、听见、接触和推断什么
- 决策链：谁承担问题、谁有权决定、谁有能力执行、谁负责后续
- 必须出现：人物、证据、行动和信息
- 禁止错误：本章最可能违反的既有事实或失败账本项
- 出口状态：本章完成的状态变化、未验证项和下一决策所有者
- 词库语义包：剧情天然承载的 1—3 个库/主题，不列逐词任务
```

高冲突、多方会谈、专业调查或信息不对称场景才增加人物认知表；普通场景不要机械填表。

## 新章循环

1. 读取项目配置、相关世界/人物规则、当前章节契约。
2. 从记忆层读取所有相关硬事实和开放线程，只读取最近三章摘要与最近一章结尾摘录。
3. 发现摘要可疑时，最多定点核查两章全文；先修摘要，再继续。
4. 付费前运行五库概念簇规划；按上下文包生成一个新版本。禁止在正文中提及“第003章”“AI 自动大纲”“审核意见”等生产信息。
5. 运行 `scripts/check_manuscript.py` 和零费用覆盖诊断（需要时），再执行 `logic-gates.md` 的 blocker 检查。
6. 无 blocker：确认该版本。只有 warning：记录，不为润色额外调用模型。
7. 有 blocker：列出最小修复目标，最多执行一次定点短补丁或全章修订；补丁必须唯一命中，修订后只复核相关门禁。
8. 仍有 blocker：保留草稿与报告，更新断点为阻塞，不继续污染后续章节。
9. 通过后更新摘要、时间线、人物状态、证据/伏笔线程和用量。

## 修订旧章

1. 读取目标章全文、前一章摘要/结尾、后一章入口状态，以及相关硬事实。
2. 保存旧摘要，完成最小修订，不顺手统一改写作者风格。
3. 比对新旧摘要：时间、位置、知识、动机、物件、证据、线程、出口状态。
4. 将受到实质影响的后续章节标为待复核，不自动重写整本。
5. 新正文写入新版本；旧确认版保留为历史，但不再进入上下文。

## 自动整书

整书运行前必须有：

- 全书章节数和每章任务；
- 核心谜题或主角目标的明确解答；
- 关键证据/物件从出现到回收的路径；
- 绝对时间轴；
- 关系线阶段变化；
- 允许的调用次数或成本停止线；
- 可写入的断点文件。

运行时逐章执行标准循环。每章通过后立即保存，不把所有章节留在一次请求或内存中。恢复时解析断点与最新确认版本；已完成章节不重新生成。

## 整书闭环

最后一章不能只制造新钩子。逐项回答：

- 开篇核心事件发生了什么，谁负责，动机是什么？
- 主角的主要目标是否达成或明确失败，代价是什么？
- 核心证据链是否由已出现且可获得的证据支撑？
- 主要人物关系是否完成本阶段变化？
- 开放线程是否已关闭、明确延期或有意留作续集？

核心答案缺失即为 blocker。续集钩子只能放在这些问题得到回答之后。

## 导出

1. 按章节号解析唯一最新确认版，拒绝重复或缺章。
2. 补齐统一格式的章节标题，但不借导出静默改剧情。
3. 运行文本检查、禁用词扫描和整书闭环。
4. 核对导出章数、记忆、断点和项目状态一致。
5. 输出 Markdown/TXT；报告残余 warning，不把未解决 blocker 称为完稿。
