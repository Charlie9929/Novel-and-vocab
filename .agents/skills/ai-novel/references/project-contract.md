# 项目契约

## 适用范围

本契约只管理本仓库 `AI小说/` 中由项目生产的 AI 小说。用户上传到阅读器的本地小说属于产品输入，不属于生成语料；不得因为 AI 小说流程而上传、改写或外发。

## 目录职责

每部作品位于 `AI小说/作品/<作品名>/`：

| 目录 | 唯一职责 |
| --- | --- |
| `00-项目控制/` | 项目配置、授权模式、断点、用量台账、禁用名词 |
| `01-世界观/` | 物理、制度、能力和题材规则 |
| `02-人物/` | 身份、目标、关系、底线、知识与能力范围 |
| `03-剧情总纲/` | 核心冲突、因果主线、结局闭环 |
| `04-分卷大纲/` | 阶段目标、高潮和阶段性回收 |
| `05-章节大纲/` | 可执行章节契约，不存正文 |
| `06-场景草稿/` | 所有未确认和修订版本 |
| `07-已确认章节/` | 每章已过门禁的版本化正文 |
| `08-记忆与连续性/` | 章节摘要、人物状态、绝对时间线、证据/伏笔线程 |
| `09-审核与修订/` | 结构化问题、修复结果和残余风险 |
| `10-导出/` | 按最新确认版本组装的交付稿 |

根级 `AI小说/` 是模板和说明，不是具体作品。新作品必须放入 `AI小说/作品/`。

## 权威版本解析

同一章节号出现多个文件时：

1. 只在 `07-已确认章节/` 中选择。
2. 优先显式版本号最大的文件；无版本号视为早于任何 `v2`、`v3`。
3. 如果有两个文件无法确定先后，停止生成并记录版本冲突。
4. 草稿、审核、导出副本和旧确认版本不得进入新章上下文。
5. 修订早期章节后，比对新旧摘要；事实、人物状态、证据、线程或结尾变化时，把受影响的后续章节标成待复核。

不要用文件修改时间代替版本语义。

## 五库共文

- 一本作品只有一份中文基础正文。
- CET4、CET6、考研英语、IELTS、TOEFL 是五个独立学习视图，不是五条剧情。
- 用户只选择词库和故事，不选择一个个英文目标词。
- 生产端把覆盖缺口聚合成“场景语义包”，例如现场行动、责任冲突、档案论证、跨国公共服务、实验研究；场景首先要对剧情有用。
- 不要求一段或一章同时服务五库。以连续约三章或一个小剧情单元观察平衡。
- 同一 lemma 应尽量出现在多个自然语境；不能自然出现就撤掉，不为覆盖率改变人物底线或塞说明段。
- 规模足够后可以制作单词库专有小说；在此之前默认五库共文。专有小说仍需独立正文审核和成本核算。

## 剧情自主权与硬边界

用户已允许 AI 在项目设定内决定剧情和章节任务。自主权不包括修改：

- 已确认事实、人物底线和世界规则；
- 叙事视角、题材边界、目标篇幅和结局类型；
- 用户列出的必须元素和禁止元素；
- 五库共文原则；
- 是否调用付费服务、部署、发布或上传内容。

若必须改变硬边界才能让故事成立，应报告选择，不得借“AI 自主决定”静默改写。

## 防撞名与防串书

在项目配置维护禁用词，包括竞品概念、已用作品核心意象、近似角色名和现成 IP。初始化和导出都扫描一次。当前已知回归项包括：

- 新作品不得复用《潮汐邮局》的“潮汐”核心意象；
- 不得再用近似的“林知遥 / 林遥”主角名；
- 不得把旧作品人物、地点、规则、章节任务或审核术语带进新作品。

## 写入和外部操作

- 已确认章节只新增版本，不静默覆盖。
- 密钥只从项目根目录 `.env.local` 读取，不打印、不复制进小说目录。
- 没有用户明确授权时，不调用付费生成、不部署、不推送、不发布。
- 批处理每章更新 `00-项目控制/自动化断点.md`；中断后从最后通过门禁的章节续跑，不重做完成章节。
