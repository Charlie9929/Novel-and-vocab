# AI 小说工作台

这里是本项目统一的 AI 小说工作区。小说正文、设定、章节记忆和审核记录都按目录保存，便于 Codex 逐章工作，也便于后续把已确认章节导出为 `.txt` 后导入背单词阅读器。

## Codex 项目 Skill

本仓库的权威 AI 小说规则位于 `.agents/skills/ai-novel/`。Codex 从仓库根目录工作时可通过 `$ai-novel` 显式调用，也可在任务匹配时自动加载。该 Skill 包含有限上下文、版本隔离、逻辑门禁、成本上限、断点恢复、五库共文契约和本项目真实失败账本。

`99-模板/ai-novel/` 是早期模板存档，不再作为权威规则；新增或修改流程时只更新 `.agents/skills/ai-novel/`，避免两份规则漂移。

所有作品还必须遵守 `00-项目控制/小说文风硬规则.md`：篇幅按 handoff、作品档位和项目配置执行，不设统一字符下限；短句不超过 15%，普通正文段落以手机端两三行为目标，前情、人物、对话、动作和主线闭环必须完整；题材不设总规则限制，禁止 AI 腔、数字堆砌、隐喻套话、机械动作、生产术语和总结式结尾。

## 工作顺序

1. 在 `00-项目控制/` 确定题材、目标读者、语言、篇幅和写作规则。
2. 在 `01-世界观/` 和 `02-人物/` 固定世界规则、人物欲望、关系和禁区。
3. 在 `03-剧情总纲/`、`04-分卷大纲/`、`05-章节大纲/` 逐级收敛剧情，不直接从一句话生成整本书。
4. 在 `06-场景草稿/` 按场景调用 DS API 生成草稿。
5. 通过 `09-审核与修订/` 完成 Codex 连贯性检查和人工确认。
6. 确认后的章节进入 `07-已确认章节/`，并把变化写入 `08-记忆与连续性/`。
7. 最终成稿放入 `10-导出/`，再导入当前阅读器。

## 自动化章节循环

完成项目配置、全书结局和章节契约后，可在项目根目录运行：

```bash
npm run ai-novel:next -- --project "AI小说/作品/手机正在直播我的葬礼"
```

命令只做一次付费正文生成；正文和压缩记忆由同一次响应返回。随后运行零付费确定性门禁并停在 Codex 语义审核，不会自动写入 `07-已确认章节/`，也不会覆盖已有文件。需要指定章节时可追加 `--chapter "AI小说/作品/.../第002章-xxx.md"`。

如果希望一次性生成整部小说，运行：

```bash
npm run ai-novel:novel -- --project "AI小说/作品/手机正在直播我的葬礼" --chapters 3
```

低成本整书命令要求所有章节契约预先存在，不会临时付费补大纲。它逐章生成草稿和记忆，执行确定性检查并写断点，但不会自行审核通过、确认或导出。Codex 发现有依据的 blocker 时，每章最多运行一次：

```bash
npm run ai-novel:repair -- --project "AI小说/作品/作品名" --draft "AI小说/作品/作品名/06-场景草稿/..." --review "AI小说/作品/作品名/09-审核与修订/...json" --runId "本轮ID" --maxChapterCalls 2
```

全部章节经 Codex 语义门禁通过后，才用审核 JSON 做零付费确认与导出：

```bash
npm run ai-novel:finalize -- --project "AI小说/作品/作品名" --chapters 12 --review "AI小说/作品/作品名/09-审核与修订/整书-Codex审核.json"
```

## 文件约定

- 草稿可以反复修改，但已确认章节不要覆盖；修改时保留版本号。
- `08-记忆与连续性/` 只保存已经发生的事实、人物状态、时间线和未闭合伏笔。
- DS API Key 只放在项目根目录的 `.env.local`，不放在本目录、不放进正文、不提交 GitHub。
- 每次外部调用都写入 `00-项目控制/生成台账.jsonl`；截断和失败调用也计入停止线。
- 每章生成都应留下“草稿、门禁、必要时修订、确认”痕迹，不把一次 API 输出直接当成成稿。
